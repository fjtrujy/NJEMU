# GitHub Pages localization

The NJEMU static website supports English and Spanish with no localization
service, cookies, or external JavaScript dependency. This applies to the landing
page, release/download cards, statistics, browser ROM converter, and MVS/CPS2
converter documentation.

## Locale selection

`web/i18n.js` selects the first supported language as follows:

1. A valid user choice saved in the `njemu-site-language` localStorage entry
   takes precedence.
2. Otherwise the primary `navigator.languages` / `navigator.language` entry is
   used. Any `es` language tag (including `es-ES` and `es-MX`) maps to Spanish;
   every other language falls back to English.
3. The dropdown in the site navigation or converter/documentation header changes
   language immediately and remembers the choice across pages. If browser
   storage is unavailable, selection continues working for the current page.

`document.documentElement.lang`, page titles, description metadata, static
labels, and accessible text update with the selected locale. API-provided
release notes, source-code identifiers, filenames and other technical data
remain unchanged. Download and ROM-conversion behavior does not depend on the
UI language. Native ROMCNV's own `-lang` option is independent of the website.

## Updating translations

English is the fallback and the canonical authored copy in HTML and JS.
Add or update its Spanish equivalent in the `spanish` catalog in `web/i18n.js`.
Static text nodes are matched against canonical English text (whitespace is
normalized); titles, relevant attributes, and document language are updated as
well. Dynamic JavaScript content must use `window.NJEMUI18n.t(source, values)`
and subscribe to `njemu:languagechange` when it needs to re-render. Interpolated
values are inserted as plain text, never as HTML.

The ROM converter documentation is generated by the Pages workflow with
Pandoc. English sources are `romcnv/README_MVS.md` and
`romcnv/README_CPS2.md`; Spanish sources are the corresponding `.es.md` files.
Both use the shared `web/doc_template.html`. Four generated HTML pages are
published (`doc_mvs.html`, `doc_mvs_es.html`, `doc_cps2.html`, and
`doc_cps2_es.html`). A visitor's language selection automatically routes to
the corresponding document without losing the path or hash fragment.

## Validation and deployment

Run:

```sh
node --test web/i18n.test.cjs web/release-model.test.cjs web/stats-model.test.cjs
```

The suite verifies browser-language detection, persistence, fallback, dynamic
message coverage, static copy coverage, documentation routing, and CLI/table
parity between the English and Spanish Markdown guides. The Pages workflow
runs this suite before copying `web/i18n.js` into `dist/` and generating the
four documentation pages with Pandoc. The existing release-download and
statistics API models remain the data source in both languages.

Manual checks should include browser language `es-ES`, changing to English,
following links between the landing page, statistics, converter and both guides,
refreshing to verify persistence, switching on mobile width, and exercising
converter format descriptions and the stable/development release feeds.
