# PSP XMB and PS Vita LiveArea artwork

PSP packages keep two version identities: `VERSION_STR` is the human-facing
release version (for example, `3.0.0`), while `NJEMU_RUNTIME_BUILD_ID` retains
the Git-derived detailed build identity (for example, `3.0.0 (abcdef12)`).
Other platforms continue to use the detailed version in their UI. The shared
`cmake/NJEMUVersion.cmake` derivation is the single source of version truth.

All artwork is grouped by emulator core under `data/artwork/<core>/`. Filenames
include their dimensions, rather than sorting by platform. The original
high-resolution background illustration is `source_1666_944.png`, while the
separately composed, visually centered small-icon artwork is
`icon_source_1254_1254.png`. Console-ready assets are derived from them using
`tools/generate_platform_artwork.swift`. The PSP XMB background keeps its
artwork on the right to accommodate the XMB icon on the left; the small PSP
icon and Vita bubble/startup assets use an independently centered logo crop.

The PSP SDK's `create_pbp_file()` builds the EBOOT using these inputs:

| PBP entry | Source | Purpose |
| --- | --- | --- |
| `PARAM.SFO` | Generated by `mksfoex` | `NJEMU <core> <release>` title, numeric `APP_VER` (`major.minor`), `MEMSIZE=1` |
| `ICON0.PNG` | `data/artwork/<core>/icon_144_80.png` | 144x80 XMB icon |
| `PIC0.PNG` | `data/artwork/<core>/pic0_480_272.png` | 480x272 transparent supplementary overlay |
| `PIC1.PNG` | `data/artwork/<core>/pic1_480_272.png` | 480x272 XMB background |
| `DATA.PSP` | Built executable | Emulator executable |

Vita VPK assets for each core use the same visual identity:

| VPK destination | Source in `data/artwork/<core>/` | Format |
| --- | --- | --- |
| `sce_sys/icon0.png` | `icon_128_128.png` | 128x128 indexed PNG |
| `sce_sys/pic0.png` | `pic0_960_544.png` | 960x544 indexed PNG |
| `sce_sys/livearea/contents/bg0.png` | `bg_840_500.png` | 840x500 indexed PNG |
| `sce_sys/livearea/contents/startup.png` | `startup_280_158.png` | 280x158 indexed PNG |
| `sce_sys/livearea/contents/template.xml` | `data/artwork/template.xml` | LiveArea XML |

These images are external source assets embedded into the PSP EBOOT or Vita
VPK at package time, not emulator runtime textures. To regenerate them on macOS,
run `swift tools/generate_platform_artwork.swift data/artwork`. The generated
PNGs are checked in so CI does not require Swift. Run
`cmake -P cmake/NJEMUArtworkValidation.cmake` to validate image metadata.

To inspect an EBOOT, run `unpack-pbp EBOOT.PBP` in an empty directory, compare
`ICON0.PNG`, `PIC0.PNG`, and `PIC1.PNG` against the corresponding files in
`data/artwork/<core>/`, and
inspect `PARAM.SFO` using `strings` or an SFO parser. The PSP CI workflow
checks these assets after installation. `APP_VER` is deliberately the SDK's
numeric major/minor representation (for example `3.0`) rather than the full
Git build identity. `DISC_VERSION` and `PSP_SYSTEM_VER` may remain at the SDK's
default `1.00`; neither is NJEMU's application version. The full SHA identity
remains available in emulator diagnostics.
